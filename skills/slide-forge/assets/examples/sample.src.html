なぜ HTML スライドなのか

セクション区切り。一呼吸おく。
Principle

スライドは読む資料ではなく、
話を届けるための舞台装置だ。

ここが今日の核。文字を詰め込むほど聴衆は「読む」ことに意識を奪われ、話が届かなくなる。1 スライド 1 メッセージ。
Why HTML

ブラウザさえあれば、どこでも同じ見た目で動く

1ファイル
CSS・JS・画像・フォントまで一つの HTML に同梱
0依存
npm もビルドサーバーも不要。10 年後も開ける
16:9
1920×1080 の固定ステージを画面に合わせて拡大縮小
数字はカウントアップする。左から順に説明。「16:9 固定」はスマホでもレイアウトが崩れない理由。

Source

1 枚のスライドは、意味のある HTML の塊

  • レイアウトは L-* クラス
  • 動きは data-anim
  • クリック送りは data-step
  • 話す内容は notes
<section class="slide L-stats">  <h2 data-anim="up">見出し</h2>  <div class="stats" data-stagger="up">    …  </div>  <aside class="notes">…</aside></section>
デザイナーでなくても読める HTML。Claude が書き、人間も直せる。
Motion

動きは「どこを見るか」を案内するためにある

  1. 話す順番に出す（先に全部見せない）
  2. 1 枚につき主役の動きは 1 つ
  3. 同じ要素は次の画面へ「移動」
フォーカスモード：新しい項目が出ると前の項目は薄くなる。右の球体は次のスライドへ「移動」する。

同じ要素がスライドをまたいで移動すると、聴衆は文脈を見失わない。

これが View Transitions API による「マジックムーブ」。PowerPoint の変形と同じ体験を HTML で。
一流の資料は、1 枚のスライドで 1 つのことしか伝えない。

— プレゼン設計の定番原則「1 スライド 1 メッセージ」
