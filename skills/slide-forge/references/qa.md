# 品質保証（QA）ガイド & レビュールーブリック

## 目次
1. 検証ループ
2. check.py の指摘コード → 直し方
3. 目視レビューで見ること（自動では分からないこと）
4. レビュールーブリック（slide-reviewer エージェントが使う）
5. 納品前チェックリスト

---

## 1. 検証ループ
```
build.py → check.py → (エラーあり) 直す → build.py → check.py … → エラー 0
         → contact-sheet を「見る」 → 気になる所を直す → 再チェック
         → 重要な発表なら slide-reviewer エージェントに独立レビューを依頼 → 指摘を反映
```
- エラーが 0 になるまで納品しない。警告は理由があれば残してよい（その理由を説明できること）。
- 自動チェックが通っても**必ずスクリーンショットを見る**。check.py は「壊れていない」ことしか保証しない。

## 2. 指摘コード → 直し方
| コード | 意味 | 直し方（上から順に試す） |
|---|---|---|
| `overflow` | 枠やステージからはみ出し | ①文章を削る ②スライドを分割 ③レイアウト変更（cards→bullets 等） ④`--cols` を減らす ⑤最後の手段で文字サイズを 1 段下げる |
| `overflow`（clipped inside container） | `overflow:hidden` の箱の中身がはみ出す | 流れる帯・背景演出など**わざと**なら、その箱を `.bleed` の中に置く（v1.4 から判定対象外）。そうでなければ中身を減らす |
| `overlap` | 文字同士が重なる | 固定位置（absolute）要素をやめて flow レイアウトへ／`.source` と本文の距離を確保／グリッドの行を分ける |
| `tiny-text` | 20px 未満 | 読めない。内容を減らしてサイズを戻す |
| `small-text` | 20–23px | 出典・注釈以外なら 28px 以上に |
| `contrast` / `contrast-aa` | コントラスト不足 | 文字色を `--fg`/`--accent-ink` に。画像上の文字は `.L-image` のグラデーション or 背景帯を敷く |
| `margin` | 安全余白（80px）内に文字 | `--pad-*` を守る。意図的なら `.bleed` |
| `density` | 文字数・箇条数が多すぎ | 1 スライド 1 メッセージに立ち返る。補足はノートへ移す。読ませない装飾の文字（流れる帯の名前一覧など）は `data-density-skip`、ループ用の複製は `aria-hidden="true"` で除外 |
| `widow` | 最終行が 1〜2 字 | 言い換えて字数調整／`<br>` で改行位置を指定 |
| `long-headline` | 見出し 4 行以上 | 見出しを短く（主張だけ残す） |
| `broken-image` | 画像が読めない | パスを確認（deck.src.html からの相対パス） |
| `text-on-image` | 写真の上の文字のコントラスト不足（実際の描画ピクセルで計測） | スクリムを文字側に（`media-bg` / `right` / `bottom` / `full`）→ `assets.py pick … --treat darken` で暗くする → 文字を写真の外へ |
| `text-over-graphic` | 文字と図形・画像が重なっている（図形に `class="solid"` か CSS で `--solid:1` を付けると検査対象） | 図形を移動・縮小、または文字の幅を詰める |
| `graphic-clipped` | 図形がスライドの外にはみ出している | 位置・サイズを調整。意図的なら `.bleed` |
| `low-res` | 画像が元の大きさの 1.3 倍超に拡大されている | 大きい元画像を選び直す／枠を小さく／背景なら `--treat blur` |
| `missing-resource` | ローカルファイルが読めない | パス・ファイル名を確認 |
| build の「no licence record」 | credits.json に記録がない画像 | `assets.py add <path> --own`（自分の素材）か出典・ライセンスを記録 |
| build の「non-commercial」 | NC ライセンス画像 | 業務・社外利用なら差し替え |
| `font-fallback` | Web フォント未読込 | オフライン環境なら `build.py --fonts embed` |
| `js-error` | スクリプトエラー | デッキ CSS/HTML の書き間違い、`data-*` の値を確認 |
| build の「mock …」 | data-mock の JSON が読めない・セル番地が画面の外 | JSON の書式、`data-src` のパス、`callouts.at`（列記号＋画面の行番号）を確認 |
| build の「N build steps」 | クリック数が多すぎ（同じ `data-step="n"` は 1 クリックとして数える） | 分割する。矢印とノードを同時に出すなら同じ番号を付ける |

目視で見つかりやすく、自動では拾えない不具合（2026-09 のセッションで実際に出たもの）:
- 自作クラスが予約名（`.bg` など）と衝突して要素が消える／全面に広がる
- ドーナツを小さくしたのにラベルが大きいまま（v1.4 で `--size` に比例するよう修正済み）
- コード欄の `<!--` などが合字で矢印に化ける（v1.4 で合字を無効化済み）
- Anime.js などで動かす要素が、動く前の位置（原点）に残って見える
- ライトテーマで `media-bg` を使うと写真が白っぽく霞む（スクリムが明るい）。暗い写真を活かしたいなら `.bg` の中に `img` を直接置く

## 3. 目視で見ること
- 見出しだけ読んで話が通るか（ゴーストデッキ）
- 各スライドの主役はどこか。視線が最初にそこへ行くか
- 同じ種類の情報が同じ見た目か（見出し位置、キッカー、強調色の使い方）
- 空きすぎ（下半分が空）・詰めすぎ。構図の重心
- 文節の変なところで改行していないか（特に数字と単位、固有名詞）
- 数字に出典があるか。例示用の仮の数字が「（例）」と明示されているか
- アニメーション: `--motion N` のストリップで、話す順に出ているか・揃うまで 1.5 秒以内か

## 4. レビュールーブリック（各 1〜5 点、PPTEval の Content / Design / Coherence を拡張）
| 観点 | 5 点 | 3 点 | 1 点 |
|---|---|---|---|
| **Message** 主張の明確さ | 全見出しが主張。ゴーストデッキで筋が通る | 一部トピックラベル | 何を言いたいか不明 |
| **Content** 内容と証拠 | 主張ごとに具体的な証拠（数字・例・図）＋出典 | 証拠が抽象的 | 証拠なし・誤り |
| **Design** 視覚設計 | 階層明確・余白十分・強調 1 点・形に変化 | 読めるが単調／やや混雑 | 重なり・はみ出し・読めない |
| **Coherence** 一貫性と流れ | 章立て明快、遷移とスタイルが統一 | 時々ぶれる | バラバラ |
| **Motion** 動きの意味 | 話す順に出る、主役 1 つ、1.5 秒以内 | 装飾的だが邪魔ではない | 過剰・注意を奪う |
| **Audience fit** 聴衆適合 | 聴衆の知識・関心・場に合う | 一般的 | 場違い |
出力形式（slide-reviewer）:
```
総合: 24/30  （Message 4, Content 4, Design 4, Coherence 5, Motion 4, Audience 3）
必須修正 (must):
  - slide 7: 見出しが「現状の課題」→ 主張に。案「手戻りの 6 割は設計起因」
推奨 (should):
  - slide 3–5: 箇条書きが 3 連続 → slide 4 を stats に
任意 (could): …
良い点: …
```
